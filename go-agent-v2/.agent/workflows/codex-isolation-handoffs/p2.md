# P2 完成报告：LSP 全量迁移到 `internal/lsp`

## 概述
已完成 P2 目标：将 `internal/apiserver` 内动态 `lsp*` handlers 全部迁移到 `internal/lsp`，`apiserver` 仅保留动态工具注册与依赖注入，并收敛诊断缓存访问面。

## 关键改动
1. 新增 `internal/lsp/ToolHandlers` 体系（基础 9 + ext 10 + 辅助 2）
   - 基础 9：`Hover/OpenFile/Diagnostics/Definition/References/DocumentSymbol/Rename/Completion/DidChange`
   - Ext 10：`CodeAction/SignatureHelp/Format/CallHierarchy/TypeHierarchy/SemanticTokens/FoldingRange/WorkspaceSymbol/Implementation/TypeDefinition`
   - 辅助 2：`AvailabilitySummary`、`DiagnosticsQuery`
2. `apiserver` 动态工具注册统一改为 `s.lspTools.*`
   - `server_dynamic_tools.go` 与 `server_dynamic_tools_*_ext.go` 仅保留注册/工具 schema
   - 删除 `func (s *Server) lsp*` 动态处理实现
3. `Server` 新增统一诊断访问面
   - `SetDiagnostics/GetDiagnostics/GetAllDiagnostics`
   - `SetupLSP` 改为通过统一访问面更新诊断缓存
4. 诊断读取收口
   - `methods_ui_code_open.go`：改为 `GetDiagnostics`
   - `methods_config.go`：改为委派 `s.lspTools.AvailabilitySummary()`
   - `lsp_diagnostics_query` 通过 `Server` 内注入的薄委派函数路由到 `s.lspTools.DiagnosticsQuery(...)`

## 兼容性说明
- JSON-RPC method 名、动态工具名、输入 schema 均未变更。
- 工具返回文本与错误消息保持原行为语义。
